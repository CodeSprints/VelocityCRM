# Translations and localization

## Interface language vs. industry profile

The application has two independent language layers:

1. **Interface language** (`vue-i18n`) — button labels, headings, messages. The switcher is in
   the application header and in Settings. Supported languages: Polish (`pl`, default) and
   English (`en`).
2. **Industry terminology** (`src/config/industries.ts`) — names for entities such as "contact"
   or "deal", depending on the selected industry profile. Terminology is translated
   independently for both interface languages.

Changing the interface language does not change the industry profile and vice versa — both layers
work together inside components through the `useIndustryLabels` composable.

## Translation files

- `src/locales/pl.json` — Polish strings.
- `src/locales/en.json` — English strings.

Both files must have an identical (nested) set of keys. The test
`tests/unit/i18n/locale-parity.spec.ts` checks this automatically every time the test suite runs.

## Adding new text

1. Add the key to `src/locales/pl.json` and the exact same key to `src/locales/en.json`.
2. Use it in a component through `t('section.key')` (the `t` function from `useI18n()`).
3. If the text depends on industry terminology, pass the relevant value as a parameter, for
   example `t('contacts.title', { plural: contactPlural })`.
4. Run `npm run test` to confirm both translation files remain in sync.

## Adding another interface language

1. Create a new file, for example `src/locales/de.json`, with the exact same set of keys as
   `pl.json`.
2. Register the language in `src/i18n/index.ts` (the `messages` object).
3. Add an option in `src/components/common/LocaleSwitcher.vue`.
4. Extend the `SupportedLocale` type and the selection logic in `useIndustryLabels` if industry
   terminology should also support the new language.

## Formatting dates, numbers and currency

Language-dependent formatting lives in `src/utils/format.ts` and uses the browser's built-in
`Intl` API (`Intl.NumberFormat`, `Intl.DateTimeFormat`, `Intl.RelativeTimeFormat`) — no extra
libraries are required, and new languages added to `Intl` are supported automatically.
